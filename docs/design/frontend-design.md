# MCNP 前端设计规范（v2 · 现代仪表盘风格）

本文档是 MCNP 统一前端（Web / Desktop / Mobile 共享 Vue 3 应用）的视觉与交互设计规范。v2 在保留 Arco Design
基础控件与既有路由契约的前提下，将视觉体系从“紧凑运维控制台”升级为“现代仪表盘风格”：卡片化信息层级、大圆角、
玻璃拟态容器、渐变强调色与更强的状态可视化。实施时按本文档重写 `frontend/app` 的外壳、样式与组件，不改路由地址
与 API 契约。

## 1. 设计目标与原则

1. **状态一眼可见**：Core 在线状态、实例运行状态、任务进度是第一优先级信息，任何页面三秒内可回答“现在健不健康”。
2. **卡片化层级**：信息按“页面 → 卡片 → 卡片内分区”三级组织；卡片是唯一的容器单位，不再使用无边框的平铺分区。
3. **克制的装饰**：渐变只用于强调色与关键视觉标记（Logo、主按钮、KPI 顶部指示条），不大面积铺渐变背景；
   玻璃拟态只用于浮层与导航外壳，正文内容卡片保持实色以保证可读性。
4. **密度可调**：默认密度比 v1 略宽松（卡片内边距 16–20 px），终端、文件列表等数据密集区域保持紧凑。
5. **不制造虚假入口**：只呈现后端已交付的能力；规划中能力不出现在导航与页面上。

## 2. 设计令牌

所有令牌定义在 `frontend/app/src/styles/base.css`（或拆分后的 `tokens.css`），以 `--mcnp-*` CSS 自定义属性暴露；
组件禁止硬编码颜色、圆角与阴影值。浅色/深色通过 `:root` 与 `:root[arco-theme='dark']` 双份定义，`system` 偏好
继续监听 `prefers-color-scheme`。

### 2.2 形状、阴影与动效

- 圆角：`--mcnp-radius-sm: 8px`（按钮、输入框）、`--mcnp-radius: 14px`（卡片）、`--mcnp-radius-lg: 20px`（模态、主要容器）。
- 阴影：卡片默认 `0 1px 2px rgba(15,23,42,0.04), 0 4px 16px rgba(15,23,42,0.06)`；悬停上浮时加深一档并配合 `translateY(-1px)`；
  深色主题阴影改为 `rgba(0,0,0,0.35)` 系。
- 间距基数 4 px；卡片内边距默认 16 px，仪表盘 KPI 卡 20 px；卡片间距 16 px。
- 动效：状态变化与悬停过渡 150–200 ms `ease-out`；页面切换不做全屏动画；全局尊重 `prefers-reduced-motion`，命中时取消所有过渡。

### 2.3 字体与排版

- 字体族延续 v1：`Inter, "Noto Sans SC", "Microsoft YaHei", system-ui, sans-serif`；数字使用 `font-variant-numeric: tabular-nums`，
  保证 KPI 与指标刷新时不抖动。
- 字号阶梯：页面标题 20 px/650、卡片标题 14 px/600、正文 13 px、辅助说明 12 px、状态徽章 11 px/600。
- 终端与代码使用等宽栈：`"JetBrains Mono", "Cascadia Code", Consolas, monospace`。

## 3. 应用外壳与信息架构

### 3.1 外壳布局

- **左侧导航栏**（桌面 ≥1024 px 常驻 232 px，可折叠为 64 px 图标栏；平板为可收起抽屉；手机为底部标签栏）：
  - 顶部为品牌区：渐变方块 Logo 标记 + “Minecraft Nexus Panel”名称。
  - 导航项：仪表盘、实例、节点、用户（仅 `user.manage`）、设置；活跃项使用左侧 3 px 渐变指示条 + 主色柔和底圆角块。
  - 底部为当前 Core 选择器卡片与用户菜单（玻璃拟态分隔区）。
- **顶栏**：左侧为当前页面标题与面包屑（实例工作区内为 Core / 实例 / 子视图）；右侧为全局状态点（Panel 连接、
  WebSocket 状态）、主题切换、语言切换与用户头像菜单。顶栏与导航栏使用 `--mcnp-glass` + 模糊，滚动时保持吸附。
- **内容区**：最大宽度 120 rem 居中，页面左右内边距 24 px（手机 12 px）。

### 3.2 路由契约（不变）

外壳升级不改变既有地址契约，浏览器历史、刷新与直接链接行为保持现状：

- `/dashboard`、`/instances`、`/instances/:coreId`、`/nodes`、`/users`、`/settings`
- `/instances/:coreId/:instanceId/:view(overview|console|config|files)?`

## 4. 页面规范

### 4.1 登录页

居中玻璃卡片（480 px 上限），顶部渐变 Logo 与产品名；表单只保留账号、密码与登录按钮；错误以卡片内顶部柔和红条呈现；
背景为页面底色 + 极淡的渐变光斑装饰（纯 CSS 径向渐变，不用图片）。

### 4.2 仪表盘 `/dashboard`

- 第一行 KPI 统计卡（4 张，响应式折行为 2/1 列）：在线 Core / Core 总数、运行中实例 / 实例总数、进行中任务、
  当前用户会话数。每张卡顶部 3 px 渐变指示条，主数字 28 px tabular 数字，下方为 12 px 辅助说明与同比状态点。
- 第二行左右两栏（2:1）：左为“实例状态分布”卡片（按 RUNNING/STOPPED/FAILED/UNKNOWN 分组的横向条形与计数）；
  右为“节点健康”卡片（各 Core 状态点、地址、延迟/版本摘要，点击进 `/nodes`）。
- 第三行“最近审计动态”卡片：具备 `audit.read` 时显示最近事件流（时间、操作者、方法、路径、结果的紧凑行），
  卡片头部保留 NDJSON 导出入口与进度反馈；无权限时整卡不渲染。
- 所有卡片数据加载中使用骨架屏（与卡片同形），加载失败在卡片内呈现重试按钮，不整页报错。

### 4.3 实例目录 `/instances`

- 页面头部：标题 + “创建实例”主按钮（渐变底），下方为筛选工具条：Core 选择、状态筛选、类型筛选、关键字搜索。
- 实例以卡片网格呈现（≥1440 px 三列，≥1024 px 两列，以下单列）。每张卡：顶部为实例名 + 状态徽章（状态色柔和底 +
  状态点），中部为类型、Core、地址端口等两行元信息，底部为一组生命周期快捷按钮（启动/停止/重启，按状态与权限禁用）
  与“进入工作区”链接。卡片悬停上浮。
- 创建向导保持既有三步（Core → 服务端类型 → 类型参数），外壳改为居中模态 + 顶部步骤指示条；各运行时的字段差异
  （Java、原生基岩端、PocketMine-MP、自定义）与 NeoForge 版本联动、自动生成实例 ID、安装任务轮询等行为不变。

### 4.4 实例工作区 `/instances/:coreId/:instanceId`

- 顶部实例头卡：实例名（20 px）、状态徽章、类型与 Core 标签、地址端口；右侧为生命周期按钮组（大一号主按钮）。
- 头部下方为子导航页签：概览 / 终端 / 配置 / 文件，与路由 `:view` 一一对应，切换不重建外壳。
- **概览**：左栏为运行时信息卡（状态机状态、PID、启动时间、退出码、运行/包装模式）与资源用量卡（CPU、内存的
  紧凑条形与 tabular 数字）；右栏为最近实例审计事件卡。
- **终端**：全宽深色终端面板（`--mcnp-console`，圆角 14 px），顶部为面板工具条（自动滚动、清屏、刷新状态），
  底部为命令输入条（圆角输入框 + 发送按钮）；保持定时刷新与游标行为。
- **配置**：左侧文档列表卡（可搜索、重新扫描、实例级校验入口），右侧编辑器卡；结构化表单按 Schema/UI Schema
  渲染为分组卡片，revision 冲突与有损写回确认沿用既有交互。
- **文件**：路径面包屑 + 工具条（新建、上传、刷新），文件表以卡片内表格呈现；传输任务在右下浮动进度卡聚合显示。

### 4.5 节点 `/nodes`

只读目录：每个 Core 一张节点卡，包含状态点、地址、版本、能力标签与 CPU 拓扑摘要（物理核/逻辑 CPU/性能类别，
未知值明确显示“未知”）。不渲染后端尚未提供的编辑/删除入口。

### 4.6 用户 `/users`（仅 `user.manage`）

用户列表卡片表格 + 顶部“创建用户”按钮；行内提供显示名称编辑、`audit.read` 授权开关与带二次确认的删除。
权限变更反馈使用行内状态，不跳页。

### 4.7 设置 `/settings`

卡片分组的本地偏好页：外观（system/light/dark 三选一卡片式单选）、语言（自动发现列表）、Desktop 专属分组
（Panel 地址、开机启动、日志目录入口）。所有偏好即时生效并持久化。

## 5. 组件规范

| 组件 | 规范要点 |
|------|----------|
| `StatCard` | KPI 卡：渐变指示条 + 大数字（tabular）+ 辅助说明 + 可选趋势点 |
| `SurfaceCard` | 通用内容卡：实色底、1 px 描边、14 px 圆角、悬停可配置上浮 |
| `StatusBadge` | 状态色柔和底 + 状态点 + 11 px 文字；状态枚举与颜色映射全应用唯一来源 |
| `PageHeader` | 标题 + 面包屑 + 右侧动作区；移动端动作收进溢出菜单 |
| `EmptyState` | 居中插画位（CSS 图形）+ 说明 + 主行动按钮 |
| `Skeleton` | 与目标卡片同形的骨架块，呼吸动画（reduced-motion 时静止） |
| `TerminalPanel` | 深色面板 + 工具条 + 输入条的组合容器 |
| `TaskProgressCard` | 右下浮动聚合卡，列出活动任务与传输进度，可收起 |

Arco Design 继续承担表单控件、表格、模态、消息反馈；上述组件只负责布局与容器风格，通过令牌覆写
（`--primary-6` 等 Arco 变量桥接到 `--mcnp-primary`）保持控件与外壳同色。

## 6. 响应式与无障碍

- 断点：`<768 px` 手机（底部标签栏、单列卡片）、`768–1023 px` 平板（抽屉导航、两列以内）、`≥1024 px` 桌面。
- 键盘可达：导航、卡片动作、页签全部可 Tab 到达且焦点环可见（2 px 主色 outline，沿用 v1 约定）。
- 状态不只依赖颜色：徽章同时包含状态点形状与文字。
- 全局尊重 `prefers-reduced-motion`；终端自动滚动等动效提供显式开关。
- 对比度：正文与背景对比度 ≥ 4.5:1，状态徽章文字 ≥ 4.5:1。

## 7. 与既有实现的关系和迁移约定

- 路由、store、API Client、i18n 自动发现、平台适配器契约不变；本次只重写外壳、样式与展示组件。
- `frontend/app/src/styles/base.css` 的 v1 令牌整体替换为 §2 令牌；组件内联样式逐步收敛到共享类与组件。
- 用户可见文案仍全部走 `frontend/app/src/locales/<语言代码>.json`，新增文案同步补齐 `zh-CN` 与 `en-US`。
- 迁移按页面分批进行：外壳与仪表盘 → 实例目录与工作区 → 节点/用户/设置；每批交付后既有交互行为（创建向导、
  终端刷新、配置保存、文件传输）必须回归通过。
